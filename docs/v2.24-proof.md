# v2.24.0 — ONE VOICE: the before and after

What the calm-and-motion release changed, measured the same way on both sides.
"Before" is v2.23.0 plus the counters and the recorder (commit `00a8284`);
"after" is v2.24.0.

## What a run puts on screen

`npm test` (the CALM section of `tools/simtest.ts`) plays the same seeds in
both builds and counts what the session actually showed. It now asserts the
right-hand column as budgets.

| Run (seed 7) | Banners / min, before → after | Floating words / min, before → after | Most words on screen at once |
| --- | --- | --- | --- |
| Lane, 2:30 against a challenger | 3.6 → 3.6 | 50.4 → 11.2 | 15 → 2 |
| Sheriff | 4.0 → 4.0 | 107.0 → 38.0 | 6 → 3 |
| Card wheel | 18.7 → 13.3 | 128.0 → 33.3 | 5 → 2 |
| Tumble | 0.0 → 0.0 | 48.0 → 27.0 | 3 → 2 |

Banner counts barely move in the lane and the Sheriff because those banners
were already rare; what changed there is that two can no longer overwrite each
other, rules of a mode are said once per player rather than every run (the
second lane on a profile shows one banner fewer), and colour waits out fights.
The card wheel loses its sub-second STUNNED banner. Every score, every
benchmark reference and every rewind fingerprint is unchanged.

## Frame time

Recorded in this repository's cloud container, which has no GPU: Chromium
renders WebGL through SwiftShader, and any page with a live or frozen WebGL
canvas composites at 1–2 seconds a frame there no matter what the interface
does. A blank page runs at 60 fps. So the numbers below split the frame into
the part the client's own interface is responsible for.

| Screen (1280×720, SwiftShader) | Before | After |
| --- | --- | --- |
| Results, interface only (arena layer removed) | 180 ms / frame | 19 ms / frame |
| Results, evidence opened (every panel of the old screen) | — | 153 ms / frame |
| Results, with the frozen arena behind it | 1,540 ms / frame | 1,038 ms / frame |
| Lane, mid-wave (arena-bound) | ~830 ms / frame | ~800 ms / frame |
| Lane, style + layout per frame (CDP) | 0.56 + 0.40 ms | 0.46 + 0.49 ms |

The results screen is the heaviest thing the interface draws. Folded, it
is roughly ten times cheaper than the wall of panels it replaced; opened, it is
still cheaper, because the looping glows and the second reveal timer are gone.

## Recordings

`node tools/record.mjs <dir> [--ref <commit>]` rebuilds the client with a short
PLAY minute, serves it and records six moments as video: boot into WARM UP, a
card opening, the countdown, a lane minute, results, and a rank-up. Under
SwiftShader Playwright's screencast stops emitting frames once a page is this
slow, so the results and rank-up moments are compared as stills; the other
four as side-by-side video.

## Deliberately removed

- The welcome glow breathing on a seven-second loop, the unread-patch dot
  pulsing forever, the clock pulsing through the last five seconds (it still
  turns red), and the rank-up's spinning rays.
- The countdown's second ring and blur; the rewind's loading card and
  percentage.
- STUNNED and NEW MARK banners (under a second, and already on the target).
- CLEAN DODGE for homing shots and for bolts aimed at somebody else; PERFECT on
  every swing (now on a chain's start and every fifth link); the card's name a
  second time when it lands; the strike reason and the new reach said twice.
- Nineteen results panels on a timer — folded, not deleted, behind one "why";
  every explanatory paragraph on PRACTICE, THE LAB, WARM UP and PROGRESS,
  likewise folded, word for word.
- View Transitions for tab changes: they could leave the top bar showing the
  previous tab under software rendering and held the page still while they
  captured. Tabs use a plain CSS entrance; the one shared-element move — a
  card becoming the run — still uses the API.
